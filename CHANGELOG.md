# Changelog

## Unreleased

- Each primitive is its own independently released asset, with its own relocation-free object, archive, proofs and checks (`tools/build_lib.sh [ASSET...]`, `proofs/tools/check.sh [ASSET...]`). The single release unit `src/m0crypto.S` is replaced by three:

  | Asset | Unit | Archive | `.text` | SHA-256 of `.text` |
  |---|---|---|---|---|
  | ChaCha20, ChaCha20-Poly1305 | `src/m0crypto_chacha20poly1305.S` | `build/lib/chacha20poly1305/libm0crypto_chacha20poly1305.a` | 3,030 | `b85f137f8356ea1d290578ce03616b3e00cff08aac7cc1104b3e9fdadfc990d3` |
  | BLAKE2s-256 | `src/m0crypto_blake2s.S` | `build/lib/blake2s/libm0crypto_blake2s.a` | 4,748 | `baf869bf5a30e81fc79956d2d61fde332555816d1cc0b0b0daede80a3dd4c68b` |
  | X25519 | `src/m0crypto_x25519.S` | `build/lib/x25519/libm0crypto_x25519.a` | 7,022 | `bb9c315f5a91a6fb35f81859c1c7562a8e084efef1bddfef2ef949dbd37fec94` |

  Each asset's bytes equal its slice of the former 14,802-byte object, so ChaCha20-Poly1305 is unchanged from 0.3.0. BLAKE2s now starts at offset 0 instead of 0xbd8, and X25519 at 0 instead of 0x1e64. In `proofs/`, the shared Lean sources compile once per asset in a Lake workspace `proofs/assets/ASSET` against that asset's artifact. Each asset has its own axiom audit and statement golden file. Modules of one primitive import no other primitive's modules.
- Proofs: one claim policy for every asset. `proofs/assets/ASSET/Audit.lean` lists exactly the asset's claims: for each global function a correctness, constant-time, read-bound and stack-bound theorem and a non-vacuity witness, then the asset's composition claims (16 for ChaCha20-Poly1305, 32 for BLAKE2s, 5 for X25519; supporting lemmas are no longer listed, since the axiom report of a claim covers its whole proof). The same list is the audit, the roots of `tools/trusted_defs.sh`, and the input of the statement golden file, which now also prints every trusted definition the claims reach (machine model, decoder, contracts, specification; not the artifact bytes, which the extraction check pins). The expected-theorem lists (`expected-axioms.txt`) and the hand-written `rootsOf` table are gone. Every kept claim statement is unchanged.
- The Poly1305 entry points `m0c_poly1305_init`, `m0c_poly1305_blocks` and `m0c_poly1305_finish` are no longer exported: they are local symbols of the ChaCha20-Poly1305 object (they never had a public header; they were global only for the test image). `.text` is unchanged. Their proved contracts stay, as internal lemmas of the AEAD proofs, whose constant-time, read and stack theorems cover them as AEAD calls them; they are no longer listed as claims. The QEMU test image calls them by their offsets in the release object (`tools/test_qemu.sh`). The artifact files now list every function offset, marked `exported` or `internal` (the X25519 field routines gain theirs).
- Proofs: the hypotheses of the composed BLAKE2s claims are named structures, `C1Hyp` and `C4Hyp` (`C1`, `C4` say the same as before). `c1_nonvacuous` states `C1Hyp` at a concrete call (it was an unaudited `example`). `c4_nonvacuous`, which stated `True`, now states `C4Hyp` for two executions whose `update` calls get different message bytes (`[1, 2, 3]` and `[4, 5, 6]` at the same address), so the constant-time hypotheses are shown to allow different secret inputs. The BLAKE2s asset has 32 claims.
- Adds X25519 (RFC 7748): `m0c_x25519(out, scalar, point)` (`include/m0crypto/x25519.h`), the argument order and return type of wolfSSL's low-level `curve25519()`. Thumb assembly generated by `tools/gen_x25519.py` (`src/x25519.S`, checked by `proofs/tools/check.sh`), with internal field routines `m0c_fe_mul`, `m0c_fe_sqr`, `m0c_fe_mulc_add`, in its own release asset.
- Buffers may be unaligned and may overlap in any way. Stack: 516 bytes. No low-order-point check.
- Clearing: returns with r0-r3 and r12 zero and zeroes the 480 stack bytes below its saved registers.
- Proofs (Lean, `proofs/`): `x25519_correct` (returns; `out` = RFC 7748 X25519 of the inputs; the clearing above; only the stack window and `out` written), `x25519_constant_time` (trace depends only on the addresses, entry SP and LR), `x25519_reads`, `x25519_stack`, all from one precondition `X25519.Pre`, in the X25519 asset's `Audit.lean` and statement golden file. Uninterrupted calls only: an interrupt pushes registers below the stack window, where the clearing does not reach. Review guide: `proofs/docs/REVIEW.md` section 9.
- Checks: `proofs/tools/mutate_x25519.py` (14 single-instruction mutants, all caught by the executable checks or the constant-time certificate) and a model-against-QEMU comparison on six sampled windows of one call (`check.sh` step 7b). No board measurement of X25519 exists.

## 0.3.0

- Adds unkeyed BLAKE2s-256 (RFC 7693): `m0c_blake2s_init`, `m0c_blake2s_update`, `m0c_blake2s_final` (`include/m0crypto/blake2s.h`), written in Thumb assembly (`src/blake2s_*.S`) and linked into the release unit `src/m0crypto.S`. `m0c_blake2s_compress` and `m0c_blake2s_copy` are internal entries.
- Release object: `.text` 7,780 bytes, SHA-256 `6249c646e284766a09eb82d4e8c09a5edb1d603a18c5c482e20b6e7e84617427`. The ChaCha20 and ChaCha20-Poly1305 code bytes are unchanged.
- Clearing: each compression zeroes its 100 bytes of stack working state and returns with r0-r3 and r12 zero. `update` and `final` return with r0-r3 zero. The context is caller memory and is not cleared.
- Proofs (Lean, `proofs/`): functional correctness of `compress`, `copy`, `init`, `update` and `final` against the specification in `Spec/Blake2s.lean`, and the composed `hash_correct` (`init; update*; final` returns and writes the RFC 7693 digest of the concatenated inputs). Constant-time trace, read-bound and stack-bound theorems for each BLAKE2s entry, with the composed `hash_constant_time`. The constant-time theorems take as public only the argument registers each entry reads (init 1, final 2, update and copy 3).
- Proofs of the clearing: the `compress` postcondition states zero locals, r0-r3 and r12. The `update` and `final` postconditions state zero r0-r3. No theorem states the stack contents left by a whole `update` or `final` call.
- Checks: the theorems are listed in `proofs/lean/Audit.lean` and locked in `proofs/tools/statements.golden`. `proofs/tools/check.sh` passes on this unit, including the QEMU tests (`tests/test_blake2s.c`) and the instruction-by-instruction comparison of the machine model with QEMU on BLAKE2s calls. The mutation run (`proofs/tools/mutate_blake2s.py`) was not repeated on this unit. No board measurement of BLAKE2s exists.
- Review guide: `proofs/docs/REVIEW.md` still describes 0.2.0. The BLAKE2s review notes (`proofs/REVIEW-blake2s.md`) are a draft written for an earlier unit.

## 0.2.0

- Proofs: secret-independent instruction and address traces, read-address bounds and per-instruction stack-pointer bounds for all three functions (`proofs/README.md`).
- Release object unchanged: `.text` 3,030 bytes, SHA-256 `b85f137f8356ea1d290578ce03616b3e00cff08aac7cc1104b3e9fdadfc990d3`.
- Proofs: Lean modules, namespaces and theorem names follow one naming convention (see `proofs/README.md`, section Naming).
- Build: `tools/build_lib.sh` takes no arguments and writes to `build/lib/` (0.1.0: `tools/build_lib.sh speed`, `build/lib/speed/`).
- Proofs: a review guide (`proofs/REVIEW.md`) lists the definitions a reader must check and against which document. The four theorems about each function share one hypothesis, and a concrete call satisfying it is exhibited.
- Proofs: `proofs/tools/check.sh` also runs the Lean specification on the RFC 8439, Wycheproof and pyca/cryptography vectors, and compares the machine model with QEMU after every instruction of sampled calls.

## 0.1.0

- `m0c_chacha20_xor`, `m0c_chacha20poly1305_encrypt` and `_decrypt` (RFC 8439).
- Release object `.text`: 3,030 bytes, SHA-256 `b85f137f8356ea1d290578ce03616b3e00cff08aac7cc1104b3e9fdadfc990d3`.
